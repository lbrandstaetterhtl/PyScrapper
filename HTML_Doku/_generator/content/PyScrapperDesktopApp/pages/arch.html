PyScrapperDesktopApp / architecture

Layers and state

MVVM, but with a static state object in the middle. Once that is clear, every view model reads the same way.

The three layers

LayerKnowsDoes not know
View (.axaml)Its view model through DataContext Models, server, file system
View modelAppData, Database, ApiClient, the servicesConcrete controls
ModelHTTP, file system, LibVLCAnything about the UI

The separation is broken deliberately in one place: several view models take the Window in their constructor, so they can open dialogs as child windows and close themselves. MainWindowViewModel, LauncherWindowViewModel and MediaConverterWindowViewModel hold such a reference.

CommunityToolkit patterns

All view models are partial, because the source generator contributes the other half. Two attributes cover almost everything:

[ObservableProperty] private string _title; public string Title { get; set; } + PropertyChanged {Binding Title}
[RelayCommand] private void Save() public IRelayCommand SaveCommand {Binding SaveCommand}

In the field tables of this documentation, a generated property is shown with its public name after an arrow, e.g. _mediaHideIcon → MediaHideIcon. That is the name the XAML binds to.

AddDownloadedMedia() is the only intended way into the collections: it appends to DownloadedMedias and, when IsPlayable is set, to PlayableMedias as well. MediaAlreadyExists(filePath) prevents duplicates during a folder scan.

Configuration and keys

AppConfig lives as data/config.json and carries four fields: ServerUrl, ServerPort, ClientApiKey and LastLoggedInUser. If the file is missing, Load() writes a default.

Neither key is ever stored in plaintext. SecretProtector encrypts through the Windows DPAPI with DataProtectionScope.CurrentUser and the fixed entropy PyScrapper.v1, and the result is stored Base64-encoded. Only the same Windows user on the same machine can decrypt it.

KeyWhere it livesSent as
ClientApiKeyAppData.Config.ClientApiKey X-Admin-Key
User API keyAppData.CurrentUser.ApiKey X-User-Key
User identifierAppData.CurrentUser.Identifier Auth

Unlike the earlier revision, the plaintext is not kept in AppData. Every call decrypts on the spot with SecretProtector.Decrypt(...) and hands the result straight to the header. EditConfigWindowViewModel does the inverse when the user edits their key: it decrypts for display and re-encrypts on save.

Logging

AppLogger is a singleton over Lazy<T> and works producer/consumer: LogNewMassage() puts the entry on a ConcurrentQueue and returns immediately, while one background task writes to logs/app.log. So there are never competing writes and never a wait on disk in the UI thread. LogDebugMessage() does the same and additionally prints to the console.

An entry is a Message of text, timestamp and type, written as yyyy-MM-dd HH:mm:ss [TYPE] text. The types used in the code are INFO, WARN and ERROR.

Services and interfaces

Interfaces bundles five contracts in one static class. They exist mainly for decoupling and testability.

InterfaceImplementationJob
IStorageServiceStorageServiceFile and folder pickers through the Avalonia StorageProvider API
IApiClientApiClientDownload, search, health, progress
IAppLoggerAppLoggerLogging
IAppDataServiceAppDataAccess to the collections and settings
IDialogServiceDialogServiceAlert, confirmation, text input

DialogService is constructed with the owner window and opens MessageBox, ConfirmationWindow and InputWindow modally. View models receive it through the constructor.

DTOs

Requests and responses are kept apart: ServerRequestData.cs holds the request types, ServerResponses.cs the response types. Both use System.Text.Json with [JsonPropertyName], because the server speaks snake_case throughout while the C# side is PascalCase.

The download response is nested: DownloadResponse contains a list of DownloadResource, each with a Context holding OutputField and MediaInfoField. From that structure the app pulls the file name, destination path, MIME type, size and the three URLs for progress, download and playback.
