Conventions in the code

  • One window, one view model, one AXAML file. The code-behind only sets the DataContext and passes the window through where needed.
  • All view models are partial, because the source generator adds properties and commands.
  • Private fields with an underscore, generated properties in PascalCase.
  • Errors are logged, not thrown. The model classes catch broadly and return neutral values.
  • The logger is held as a field: private readonly AppLogger _logger = AppLogger.Instance;
  • No dependency injection container. Dependencies arrive through constructor parameters or straight from AppData.
  • Never hold a decrypted key. Call SecretProtector.Decrypt(...) where the header is set and let the value go out of scope with the request.

Adding a window

  1. Create Views/MyWindow.axaml, use the styles from Design.axaml and embed TitleBarControl if appropriate.
  2. Views/MyWindow.axaml.cs with InitializeComponent() and setting the DataContext.
  3. ViewModels/MyWindowViewModel.cs as public partial class ... : ObservableObject, state through [ObservableProperty], actions through [RelayCommand].
  4. If the constructor touches the network or state: if (Design.IsDesignMode) return; as the first line.
  5. To close, either a CloseRequested action the view subscribes to, or the window reference passed in — both variants exist in the code base.
  6. Add the entry point in MainWindowViewModel as another [RelayCommand] and bind it in the main window's XAML.

Data flow by example

From clicking „create playlist“ to the entry appearing in the list:

LayerWhat happens
ViewThe button binds to CreatePlaylistCommand
View modelCreatePlaylist() checks the name and collects the selected media IDs
ModelDatabase.CreatePlaylistAsync() sends POST /create/playlist/
ModelOne POST /create/playlistmedia follows per assignment
StateAppData.AddPlaylist() appends the playlist to the ObservableCollection
ViewThe list updates because it is bound to that same collection

The last step is why no refresh logic is needed: views bind straight to the collections in AppData, not to copies.

ffmpeg and codecs

Two places use the tools. AudioPlayer.IsSupportedCodec() calls ffprobe to check, before playback, whether LibVLC can handle the file. MediaConverter calls ffprobe for the streams and the total duration, then ffmpeg for the conversion; the percentage comes from that duration and the progress lines on stderr. Which streams are copied and which are re-encoded is decided by the container tables described under Converting. Cancelling sets the CancellationToken and terminates the ffmpeg process.
