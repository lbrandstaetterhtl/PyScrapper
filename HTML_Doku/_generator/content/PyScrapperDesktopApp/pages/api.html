{{stat:calls}} endpoints are called by the app, spread across two classes. Click a row for parameters and a jump into the source.

Who calls what

ClassResponsible forHeaders it sends
ApiClient Download, search, health, progress, login, logout, register X-User-Key + Auth on the authenticated calls; /health, /login and /register go out without one
Database Everything around media, playlists, settings and users X-User-Key + Auth for the per-user routes, X-Admin-Key + Auth for the ones the server guards with the admin key

Both keys are held encrypted and decrypted per call: SecretProtector.Decrypt(AppData.Config.ClientApiKey) for the admin key and SecretProtector.Decrypt(AppData.CurrentUser.ApiKey) for the user key. The plaintext never sits in a field.

The base URL is rebuilt on every call as {ServerUrl}:{ServerPort}{path}. Each method creates its own HttpClient inside a using.

Error behaviour is the same in both classes: on a status code outside the success range an Exception is thrown, the catch logs an ERROR line and a neutral value is returned. The calling UI therefore sees empty lists or null rather than an exception.
