Running, testing, shipping

Starting

The PowerShell script prefers the venv in the server folder and otherwise falls back to the Python on PATH. It changes into the server directory first — that matters, because Session derives its cookie path from the working directory.

WhatValue
Commandpython -m uvicorn server:app --host 127.0.0.1 --port 8765
Scriptscripts/startServer.ps1
Dependenciesfastapi, uvicorn[standard], pydantic, certifi, yt-dlp, playwright, bcrypt, dotenv, pywin32
SecretADMIN_KEY in .env next to server.py
Log filelogs/server_runtime.log

After installation Playwright also needs its browser binaries (playwright install chromium). Without them every provider that relies on sniffing will fail. ffmpeg and ffprobe must be on PATH as well: every STREAM download now runs through the engine's codec probe and, where needed, the ffmpeg muxer. A missing binary surfaces as FFmpegNotFoundError.

pywin32 is only imported on Windows (named pipes for the ffmpeg inputs), but it is listed unconditionally, so pip install -r requirements.txt fails on Linux and macOS. Install the other packages by hand there.

Tests

The suite in tests/ needs no test runner. The scripts read the admin key from the .env, send real requests to a running server and write their results to their own log file.

ScriptCovers
run_tests.py Entry point that runs the other suites in turn and reports a combined result
test_common.py Shared harness: request helpers, headers, evaluation and logging used by all suites
download_tests.py Input validation of /download/video-audio
search_tests.py The same for /search
create_delete_tests.py All create and delete routes, valid and invalid alike

The shape is the same everywhere: a list of cases with an expected status code, an evaluate() function and a main() that counts through them. New cases go into the constant list at the top of the file, not into the code below it.

Tests authenticate as a user now

Because most routes moved from X-Admin-Key to X-User-Key plus Auth, the suites need a user that exists in the database and the matching key. The shared setup lives in test_common.py; a suite run against a fresh database will fail on authentication before it ever reaches the case it meant to check.

LOCAL downloads are switched off

receive_download() raises ValueError("Local Download was turned off by administrator because of pending rework") as the first statement of the LOCAL branch, so a request with download_strategie = LOCAL is answered with a 400. The code below the raise is unreachable but kept. Only STREAM is usable at the moment; the desktop app and the web interface both send stream.

The reason is on the engine side: the HLS dispatcher's local path still calls MasterHLSDownload and IndexHLSDownload with their old constructor signatures and would fail anyway.

Error handling in the routes

The handlers catch broadly and translate to HTTP codes. The pattern repeats:

CaughtBecomes
ValueError, TypeError, ArgumentError400, prefixed „Invalid type for“
TaskFailedError500 with the text of the exception
DRMProtectedMediaError422 in the download route
sqlite3.IntegrityError409 in the CRUD routes
UnicodeDecodeError ends up in the wrong branch

UnicodeDecodeError inherits from ValueError through UnicodeError and is therefore caught by the first branch. The client gets „Invalid type for 'utf-8' codec can't decode byte ...“ and a 400, although the fault is neither the type nor the client. On top of that only data is logged, not the exception — so there is no traceback to look at.

A dedicated except UnicodeDecodeError ahead of the ValueError branch and a traceback.format_exc() in every handler fixes both.
