Access patterns

connect_db() opens the file with a 20 second timeout and sets three pragmas on every connection:

PragmaEffect
journal_mode=WALReaders no longer block the writer, which is what a polling client plus a running download needs
foreign_keys=ONThe declared constraints and every ON DELETE CASCADE are actually enforced
busy_timeout=5000A blocked write waits five seconds instead of failing immediately with database is locked

Each handler opens and closes its own connection; there is no pool and no ORM layer, every query is hand-written SQL with placeholders. row_factory is sqlite3.Row, so handlers index rows by column name.

Writes still run on the event loop

The handlers are async but call sqlite3 directly. WAL and the busy timeout take the edge off, but a slow write still blocks the loop for its duration. Wrapping the database calls in asyncio.to_thread would move them off it entirely.

Ownership lives in the code, not in the schema

Nothing in the schema restricts a row to its owner — UserIdentifier is just a foreign key. The actual check is owns_record() in the handler, against the OWNED_TABLES allowlist. A new table with a UserIdentifier column is not protected until it is added to that tuple.
