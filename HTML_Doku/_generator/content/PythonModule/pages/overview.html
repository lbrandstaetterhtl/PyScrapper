PythonModule

The engine behind PyScrapper. It takes a URL, works out where the real media data lives, decides which transfer mechanism sits behind it and delivers the bytes either into a file or as a stream. The LocalServer is only the HTTP shell around it.

The packages

The code is cut along responsibility, not technology. The fastest way to find something is through this split:

PackageResponsibilityLook here when
core.network HTTP with a cookie jar, the Playwright browser layer, byte streaming (including ranged and multi-range fetches), fetching HTML and JSON a page never loads at all, or cookies go missing
core.download The three download mechanisms FILE, HLS and UMP plus the dispatcher in front of them the download starts but arrives wrong, or not at all
core.ffmpeg Codec probing with ffprobe, the container table, and the muxer that joins separate video and audio streams or re-wraps them into the requested container the bytes arrive but the file will not play, or ffmpeg exits with an error
core.processes An asyncio wrapper around subprocesses with any number of input pipes (POSIX pipes or Windows named pipes) ffmpeg hangs, a pipe breaks, or something works on Linux but not on Windows
core.models Every data class and enum that travels between the layers, plus the error types you want to know which fields a context really has
core.general Argument checking, regex helpers, file conversion, progress reporting an ArgumentError is thrown and you are looking for its source
providers One module or package per platform, each with search() and getMediaInformation() one particular site misbehaves
models Pydantic requests and responses, the provider registry you want to change the HTTP schema or a provider alias

Where to start reading

Four places explain almost the whole system between them. Once you have read those, any further provider takes a few minutes to understand.

  1. makeProviderResult() — decides which of the discovered URLs actually gets downloaded.
  2. DownloadContext — the object handed through every layer from that point on.
  3. DownloadDispatcher — distributes the contexts across the three mechanisms.
  4. Dispatcher._asyncProcessSources() — where every stream ends: probe the codecs, pass the bytes through untouched or hand them to ffmpeg.
How this documentation is produced

Everything except the explanatory prose is generated from the code by HTML_Doku/_generator/build_docs.py: signatures, fields, defaults, line numbers, source, the call graph and the numbers on this page. The prose lives next to it in _generator/content/. Run the script after a change and the module pages are current again; the prose only moves when someone edits it. Docstrings are rare in this project, so in many places only the signature is shown.
