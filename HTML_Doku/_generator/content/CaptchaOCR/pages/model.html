The network

A deliberately small convolutional classifier: one 28×28 letter in, one score per character out. Its shape is not hard-coded — CNN::new builds it from config.json, and the weights in model.safetensors must match what the config describes.

Layers

{{gen:model_layers}}

Each convolution has stride 1 and no padding, so it shrinks the image by kernel_size − 1. The channel count starts at 16 and doubles with every layer. Whether a 2×2 max-pool follows is taken from pool_after. After the last layer the feature map is flattened and a single linear layer maps it to {{stat:vocab}} logits.

Forward pass

CNN::forward runs conv → ReLU → (max-pool) per layer, flattens from dimension 1 and applies the linear layer. There is no dropout or batch norm; inference is deterministic.

top_k applies softmax to the logits and keeps the max_candidates most likely characters for that position. It also checks that the model's output width equals the vocabulary length and fails with a clear message otherwise.

From letters to strings

candidates is a beam search over the positions. It starts with the empty string, extends every kept prefix with every candidate character of the next position, scores the result by the sum of log-probabilities, and keeps the best max_candidates. At the end the scores are turned back into probabilities; img_to_text discards them and returns only the strings, best first.

With max_candidates = {{stat:max_candidates}}, {{stat:max_candidates}} alternatives per letter are considered, but only {{stat:max_candidates}} complete strings come back. Raising it makes Bandcamp's retry loop try more answers per captcha at the cost of more form submissions.

Vocabulary

Vocab is the vocab_str from the config as a list of characters; class i of the network is character i of that string. Digits, upper case and lower case — {{stat:vocab}} classes. The order has to be exactly the one used in training.

config.json

Config::load reads config.json from the model directory. If the file does not exist, it writes Config::default() there and uses that.

A missing model file is not an error

CNN::load loads the weights only if model_path.exists(). Without the file the network keeps the random weights it was initialised with, and img_to_text happily returns nonsense. A wrong ocr_dir therefore looks like a bad model, not like a configuration mistake. Returning an error when the file is missing would make this visible.

Two settings that only look configurable

device = "cuda" or "metal" needs candle built with the matching feature; Cargo.toml enables neither, so both fail at runtime. And a pool_after shorter than conv_count indexes past the end of the vector, which panics in Rust and reaches Python as pyo3_runtime.PanicException instead of a ValueError.
