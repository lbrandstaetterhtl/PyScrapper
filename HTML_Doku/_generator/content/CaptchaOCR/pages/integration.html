CaptchaOCR / integration

Python and Bandcamp

The extension exposes exactly one function. Its only caller is the Bandcamp search, which uses it to get past the „Client Challenge“ page Bandcamp shows to repeated or automated searches.

The Python API

CallReturnsRaises
ocr.img_to_text(image_path: str, ocr_dir: str) list[str] ValueError
  • image_path — a file on disk; the function does not take bytes.
  • ocr_dir — the model directory holding config.json and the weights, e.g. PythonModule/providers/ocr.
  • The result holds at most max_candidates strings, most likely first. Their probabilities are computed but not returned.
  • Every Rust error (unreadable image, bad config, tensor shape mismatch) is converted into a ValueError with the message text. A panic surfaces as pyo3_runtime.PanicException.

The function holds the GIL for its whole run and loads the config and the weights again on every call. For the occasional captcha that is fine; for bulk use the model would have to be cached.

1import ocr
2candidates = ocr.img_to_text("captcha.jpeg", "PythonModule/providers/ocr")
3print(candidates)   # up to max_candidates strings, best first

How Bandcamp uses it

The full sequence is in the Bandcamp captcha flow. In short: bandcamp_search.py loads the search page, and if _isClientChallenge() recognises the challenge it opens the page in a headless browser, cuts the Base64 JPEG out of the HTML, writes it to a temporary file in the working directory and calls ocr.img_to_text with OCR_PATH (the providers/ocr folder). The browser types the candidates into #capInput one after another; when it stops, its cookies are written to the session's cookie file, the session reloads them and the search is repeated — up to CAPTCHA_RETRIES (3) times before the search gives up with a TaskFailedError.

The provider modules are documented in the engine documentation (HTML_Doku/PythonModule.html, page „providers“).

The engine does not load without the module

bandcamp_search.py has import ocr at the top, and providers/__init__.py imports every provider. If the extension is not installed, the whole engine — and with it the server — fails to start with ModuleNotFoundError: No module named 'ocr', even if nobody ever searches Bandcamp. A lazy import inside _solveCaptcha() would confine the dependency to the one place that needs it.

Success is only detected when the click fails

BandcampCaptchaBrowser.sendCaptchaSolutions() fills in a candidate and clicks #capSubmit. It returns True only from the except branch, i.e. when the click raises and the page content has changed. If the click goes through normally, the loop moves on to the next candidate and the method finally returns False even when the captcha was solved. The search still repeats afterwards, so a solved captcha is noticed one round later; the log line „Couldn't solve captcha“ can therefore be misleading.

Trying it by hand

test.py runs the OCR on one image and prints the candidates and the time taken:

1python test.py captcha.jpeg --ocr-dir PythonModule/providers/ocr

Without --ocr-dir it uses the environment variable OCR_DIR or a hard-coded path from the author's machine. Its -n option defaults to 5, but the module never returns more than max_candidates ({{stat:max_candidates}}) strings.
