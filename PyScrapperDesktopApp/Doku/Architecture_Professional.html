PyScrapper - Datenmodelle & Architektur

Technische Dokumentation der Applikations-Struktur
Architektur-Übersicht: Die Anwendung folgt dem MVVM-Pattern (Model-View-ViewModel). Benutzer interagieren mit der View (UI), die über ViewModels mit Datenmodellen kommuniziert. Alle Daten werden in einer lokalen SQLite-Datenbank gespeichert.

5. ViewModels (Präsentations-Logik)

MainWindowViewModel
Zentrale ViewModel des Hauptfensters. Verwaltet: Video-Liste, Playlists, Filter, Sortierung
ScrapWindowViewModel
Verwaltet Suche und Download. Befehle: Search, Scrap, Validierung
MediaPlayerViewModel
Steuert Musik-Abspieler. Befehle: Play, Pause, Next, Volume
FilterWindowViewModel
Verwaltung der Filter-Dialog. Befehle: Apply, Cancel
ProgressBarViewModel
Zeigt Download-Fortschritt. Polling der API: GetDownloadProgress
HealthViewModel
Zeigt Server-Status an. Periodische Health-Checks

Python 3.x (FastAPI/Flask)

Logging
Lokale Log-Dateien (app.log, server_runtime.log)

7. Datenfluss: Ein Beispiel

Szenario: Benutzer sucht ein YouTube-Video und lädt es herunter

1. Benutzer gibt "Lofi Beats" ein und klickt "Suchen"
2. MainWindowViewModel.SearchCommand aufgerufen
3. ScrapWindowViewModel.Search() erstellt SearchRequestData
4. ApiClient.SendSearchRequest() sendet HTTP POST /search
5. Python-Server verarbeitet Anfrage und gibt JSON zurück
6. ApiClient deserializado JSON zu SearchResponse
7. Ergebnisse in ObservableCollection gespeichert
8. UI bindet an Collection, zeigt Videos mit Thumbnails
9. Benutzer wählt Video und klickt "Download"
10. DownloadRequestData erstellt
11. ApiClient.SendScrapRequest() HTTP POST /download
12. Python-Server startet Download, gibt ID zurück
13. ProgressBarWindow zeigt Fortschritt
14. ProgressBarViewModel.StartProgress(id) startet Polling
15. Jede Sekunde: HTTP GET /download/progress/{id}
16. Wenn fertig: DownloadedMedia-Objekt erstellt
17. In Datenbank gespeichert
18. UI aktualisiert automatisch (Binding)
