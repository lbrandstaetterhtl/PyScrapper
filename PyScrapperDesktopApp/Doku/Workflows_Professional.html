1. Download-Workflow

Szenario: Benutzer sucht Medien über einen Provider, wählt Treffer aus und startet den Download. Der Ablauf zeigt Validierungen, API-Anfragen und Fehlerbehandlung. 
 flowchart TD
     Start(["Benutzer startet Suche"]):::input
     Query["Eingabe: Suchtext"]:::input
     Check1{"Suchtext validieren"}:::decision
     Check1 -->|Leer| Error1["Fehler: Text erforderlich"]:::error
     Error1 --> Query
     
     Check1 -->|OK| Search["API POST /search"]:::process
     Search --> Server["Python-Server verarbeitet Anfrage"]:::process
     Server --> Response{"Ergebnisse vorhanden?"}:::decision
     
     Response -->|Nein| Error2["Keine Ergebnisse gefunden"]:::error
     Error2 --> Query
     
     Response -->|Ja| Results["Ergebnisse anzeigen"]:::success
     Results --> Select["Benutzer wählt Video"]:::input
     
     Select --> Download["Speicherort auswählen"]:::input
     Download --> API2["API POST /download"]:::process
     API2 --> Backend["Backend startet Download"]:::process
     
     Backend --> GetID["Download-ID erhalten"]:::success
     GetID --> Poll["Fortschritt abrufen Loop"]:::process
     
     Poll --> Status{"Download Status?"}:::decision
     Status -->|Running| Update["Fortschritts-Update"]:::process
     Update --> Poll
     
     Status -->|Finished| FileCheck{"Datei existiert?"}:::decision
     FileCheck -->|Nein| Error3["Fehler: Datei nicht gefunden"]:::error
     Error3 --> End1["Abbruch"]:::error
     
     FileCheck -->|Ja| Create["DownloadedMedia-Objekt erstellen"]:::success
     Create --> Save["In Datenbank speichern"]:::success
     Save --> Refresh["UI aktualisieren"]:::success
     Refresh --> End(["Download erfolgreich"]):::success
     
     classDef success fill:#2ecc71,stroke:#27ae60,stroke-width:2px,color:#000
     classDef error fill:#e74c3c,stroke:#c0392b,stroke-width:2px,color:#fff
     classDef process fill:#3498db,stroke:#2980b9,stroke-width:2px,color:#fff
     classDef decision fill:#f39c12,stroke:#d68910,stroke-width:2px,color:#000

2. Anwendungs-Initialisierung

Szenario: Die Anwendung startet, lädt Einstellungen, Datenbank-Inhalte und prüft Medien auf Verfügbarkeit. 
 flowchart TD
     Boot(["Applikation startet"]):::input
     Boot --> Splash["Splash-Screen anzeigen"]:::process
     Splash --> LoadSet["Einstellungen laden"]:::process
     
     LoadSet --> CheckSet{"Einstellungen OK?"}:::decision
     CheckSet -->|Nein| DefSet["Standard-Einstellungen setzen"]:::process
     DefSet --> SaveSet["Einstellungen speichern"]:::success
     CheckSet -->|Ja| ApplyTheme
     SaveSet --> ApplyTheme
     
      ApplyTheme["Design-Theme anwenden"]:::process
      ApplyTheme --> LoadMedia["Medien aus DB laden"]:::process
     
      LoadMedia --> LoopVal["Für jedes Medium validieren"]:::process
     LoopVal --> FileExist{"Datei existiert noch?"}:::decision
     
     FileExist -->|Nein| Remove["Aus DB entfernen"]:::error
     Remove --> NextVal
     
     FileExist -->|Ja| CodecCheck["Codec-Unterstützung prüfen"]:::process
     CodecCheck --> CodecOK{"Codec OK?"}:::decision
     
     CodecOK -->|Nein| NotPlay["Als nicht abspielbar markieren"]:::error
     NotPlay --> NextVal["Nächstes Video"]:::process
     
     CodecOK -->|Ja| SetPlay["Als abspielbar markieren"]:::success
     SetPlay --> NextVal
     
     NextVal --> HasMore{"Mehr Videos?"}:::decision
     HasMore -->|Ja| LoopVal
     HasMore -->|Nein| LoadPlay["Playlists laden"]:::process
     
     LoadPlay --> Scan["Download-Ordner scannen"]:::process
     Scan --> Ready["Alle Daten geladen"]:::success
     Ready --> MainWindow["Hauptfenster anzeigen"]:::process
     MainWindow --> Complete(["Applikation bereit"]):::success

3. Filter-Anwendung

Szenario: Benutzer setzt Filter (Suchtext, Datum, Format, Playability) und die Medienliste wird gefiltert. Die ursprüngliche Liste wird gesichert und bei Bedarf wiederhergestellt. 
 flowchart TD
     Start(["Filter-Dialog öffnen"]):::input
     Config["Benutzer setzt Filter-Kriterien"]:::input
     Apply["Anwenden klicken"]:::input
     
     Apply --> Backup["Original-Liste als Backup speichern"]:::success
     Backup --> Clear["Angezeigte Liste leeren"]:::process
     Clear --> Loop["Für jedes Video prüfen"]:::process
     
     Loop --> Check1{"Suchtext Match?"}:::decision
     Check1 -->|Nein| Skip1["Überspringen"]:::error
     Skip1 --> Next["Nächstes Video"]:::process
     
     Check1 -->|Ja| Check2{"Datum im Bereich?"}:::decision
     Check2 -->|Nein| Skip2["Überspringen"]:::error
     Skip2 --> Next
     
     Check2 -->|Ja| Check3{"Format ausgewählt?"}:::decision
     Check3 -->|Nein| Skip3["Überspringen"]:::error
     Skip3 --> Next
     
     Check3 -->|Ja| Check4{"Nur abspielbar?"}:::decision
     Check4 -->|Ja und nicht abspielbar| Skip4["Überspringen"]:::error
     Skip4 --> Next
     
     Check4 -->|OK| Add["Zur gefilterten Liste hinzufügen"]:::success
     Add --> Next
     
     Next --> HasMore{"Mehr Videos?"}:::decision
     HasMore -->|Ja| Loop
     HasMore -->|Nein| Result["Gefilterte Liste anzeigen"]:::success
     Result --> Close["Filter Dialog schließen"]:::input
     Close --> Finish(["Filter angewendet"]):::success

4. Musik-Abspieler State Machine

Szenario: MediaPlayerControlViewModel steuert den AudioPlayer. Die Wiedergabe wechselt automatisch zwischen Tracks und reagiert auf Pause, Skip und Stop. 
 flowchart TD
      Init(["MediaPlayerControlViewModel initialisieren"]):::process
     Init --> Standby(["STANDBY-Modus"]):::process
     
     Standby --> LoadCmd["Playlist laden"]:::input
     LoadCmd --> Store["Playlist im Player speichern"]:::process
     Store --> Check1{"Shuffle aktiviert?"}:::decision
     
     Check1 -->|Nein| Order["Original-Reihenfolge"]:::success
     Check1 -->|Ja| Random["Zufällige Reihenfolge"]:::process
     Random --> Play1
     Order --> Play1
     
     Play1["Ersten Track laden"]:::process
     Play1 --> Check2{"Datei existiert?"}:::decision
     Check2 -->|Nein| Skip["Skip Track"]:::error
     Skip --> Play1
     Check2 -->|Ja| Playing(["PLAYING - Musik läuft"]):::success
     
     Playing --> Control["Benutzer-Kontrolle"]:::input
     Control --> Action{Aktion?}:::decision
     
     Action -->|Pause| Paused["PAUSED-Modus"]:::process
     Paused --> Resume["Play Button"]:::input
     Resume --> Playing
     
     Action -->|Volume| Vol["Lautstärke ändern"]:::process
     Vol --> Playing
     
     Action -->|Next| Next["Nächster Track"]:::process
     Next --> Playing
     
     Action -->|Stop| Stop["STOPPED"]:::error
     
     Action -->|Track endet| Auto["Automatisch nächster"]:::success
     Auto --> Playing

5. MVVM Data Binding

Konzept: Wenn sich Observable Properties oder Collections ändern, aktualisiert sich die UI automatisch. Manuelle Refresh-Schritte sind im Normalfall nicht nötig. 
 flowchart TD
     User(["Benutzer-Aktion"]):::input
     User --> Click["Button klick / Text eingeben"]:::input
     
     Click --> Command["Command.Execute aufgerufen"]:::process
     Command --> Logic["Geschäftslogik ausgeführt"]:::process
     
     Logic --> PropChange["Observable Property ändert sich"]:::process
     PropChange --> Event["PropertyChanged Event auslösen"]:::success
     Event --> Binding["Data Binding erkennt Änderung"]:::process
     Binding --> UIUpdate["UI Control aktualisiert sich"]:::success
     UIUpdate --> Visual["Benutzer sieht Änderung"]:::success
     
     Logic --> CollChange["Collection wird modifiziert"]:::process
     CollChange --> CollEvent["CollectionChanged Event"]:::success
     CollEvent --> ListBind["ListBox neu gerendert"]:::process
     ListBind --> Visual2["Neue Items erscheinen"]:::success
     
     Logic --> APICall["API-Call startet async"]:::process
     APICall --> Background["Im Hintergrund laufend"]:::process
     Background --> Complete["Ergebnis verfügbar"]:::success
     Complete --> UpdateData["Daten aktualisieren"]:::process
     UpdateData --> UIAPI["UI zeigt Ergebnis"]:::success
