1. PyScrapper Desktop - Scraping Ablaufdiagramm

Dieses Flussdiagramm visualisiert den Such- und Download-Prozess zwischen der Avalonia UI (C#) und dem lokalen Python-Server.
Tipp: In allen drei Diagrammen kannst du mit dem Mausrad zoomen, mit den Controls interagieren und die Diagramme herumziehen!

        flowchart TD
            A([User öffnet die Suche]) --> B[/Eingabe Suchbegriff & Klick auf Search/]
            
            subgraph Frontend [C# Avalonia Frontend]
                B --> C{ApiClient.cs}
                C --> E[Frontend zeigt Such-Ergebnisse an]
                E --> F[/User wählt ein Medium & klickt 'Scrap'/]
                F --> G[Zeigt FilePicker: Speicherort wählen]
                G --> H{ApiClient.cs}
                H --> I[Öffnet ProgressBarWindow]
                I --> J((Progress Polling))
                J -- Loop bis 100% --> J
                J -- Fertig --> K[Speichert Medium in AppData]
                K --> L([Update der MainWindow Ansicht])
            end

            subgraph Backend [Local Python Server]
                D[(Python Web-API)]
            end

            C -- "POST /search" --> D
            D -- "JSON: Ergebnisse & Thumbnails" --> C

            H -- "POST /download" --> D
            D -- "Download-ID guid" --> H

            J -- "GET /download/progress/id" --> D
            D -- "Status, % Fortschritt, Speed" --> J

2. Architektur-Layout (MVVM Struktur)

Zeigt, wie die Schichten in der App miteinander kommunizieren. Avalonia Views sprechen mit ViewModels, welche sich wiederum der Models bedienen.

        flowchart LR
            subgraph V [Views /.axaml]
                MW[MainWindow]
                LW[LauncherWindow]
                SW[ScrapWindow]
            end
            subgraph VM [ViewModels]
                MWVM[MainWindowViewModel]
                LWVM[LauncherWindowViewModel]
                SWVM[ScrapWindowWithSearchViewModel]
            end
            subgraph M [Models / Services]
                AD[AppData]
                AC[ApiClient]
                DB[DatabaseOperations]
            end
            subgraph EXT [External Backend / Storage]
                SQL[(SQLite DB)]
                PY[Local Python Server]
            end

            MW -->|DataBinding| MWVM
            LW -->|DataBinding| LWVM
            SW -->|DataBinding| SWVM

            MWVM -->|Read / Write| AD
            SWVM -->|Calls| AC
            LWVM -->|Reads Settings| DB

            DB -->|SQLite queries| SQL
            AC -->|HTTP JSON requests| PY

3. App Start-Lebenszyklus (Lifecycle)

Der Startup-Prozess von der ersten Initialization der GUI bis zur vollständig geladenen Benutzeroberfläche.

        stateDiagram-v2
            [*] --> Init : OnFrameworkInitializationCompleted
            Init --> LauncherWindow : Startet Ladefenster
            LauncherWindow --> DatabaseOperations : Laedt SQLite AppDaten
            LauncherWindow --> [*] : User Bricht ab
            DatabaseOperations --> MediasValidate : Pruefe Dateien auf Festplatte
            MediasValidate --> ScanFolder : App.ScanFolder
            ScanFolder --> CheckDiff : Fuege neue Medien hinzu
            CheckDiff --> MainWindow : Oeffnet Hauptfenster
            MainWindow --> [*] : App Ready

4. Datenmodell & Relationen (ER-Diagramm)

Zeigt, wie die zentralen Datenstrukturen für Medien, Playlists und App-Einstellungen aufgebaut sind und vom zentralen State-Manager (AppData) gehalten werden.

        erDiagram
            AppData ||--o{ DownloadedMedia : contains
            AppData ||--o{ Playlist : manages
            AppData ||--|| Settings : uses
            
            DownloadedMedia {
                int Id
                string Title
                string Url
                string MediaType
                string DownloadPath
                boolean IsPlayable
                datetime DownloadedAt
                string Identifier
            }
            
            Playlist {
                int Id
                string Name
                string ImagePath
                string MediaListIds
            }
            
            Settings {
                string DownloadPath
                string ServerUrl
                boolean DarkModeEnabled
            }

5. Ablauf der Codec-Konvertierung

Visualisiert den Workflow, wenn ein Benutzer aus dem Hauptfenster eine Datei in einen unterstützten Codec (z.B. H264) umwandeln möchte.

        flowchart TD
            A([Klick auf Convert Codec]) --> B[FilePicker: Videodatei auswaehlen]
            B --> C{Datei existiert?}
            C -- "Nein" --> D[Zeige Error MessageBox]
            C -- "Ja" --> E{User bestaetigt Umwandlung?}
            E -- "Nein" --> F([Abbruch / Return])
            E -- "Ja" --> G[Startet CodecConverterWindow]
            G --> H((Konvertierungsprozess laeuft))
            H --> I{Erfolgreich beendet?}
            I -- "Nein" --> J[Schreibe Abbruch in App.log]
            I -- "Ja" --> K[Zeige Success MessageBox]
            K --> L([Konvertierte Datei steht als IsPlayable zur Verfuegung])

7. Medienwiedergabe Zustandsmaschine (Playback State)

Zeigt, wie der interne AudioPlayer (mit LibVLC) den Status der Medienwiedergabe verwaltet und wie Playlisten die Ladevorgänge steuern.

        stateDiagram-v2
            [*] --> Idle : App gestartet
            Idle --> Loading : LoadMedia oder LoadAndPlay
            Loading --> Playing : Starte Wiedergabe
            Playing --> Paused : User klickt Pause
            Paused --> Playing : User klickt Resume
            Playing --> Stopped : User klickt Stop oder Ende des Tracks
            Stopped --> Loading : Lade naechsten Track aus Playlist
            Stopped --> Idle : Keine Tracks mehr
            Playing --> [*] : App verlassen
